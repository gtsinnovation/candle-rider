# Fix: trim TRENCHES_COINS from 16 to 5 — removes 11 coins, 5 of them art-less, and restores $LEGEND as the top of the ladder

| Field | Value |
|---|---|
| File | `client/src/scenes/paths/trenchesCoins.js` |
| Category | Content / Correctness |
| Severity | high |
| Effort | Low |
| Pairs with | `i9.md` (adds the per-coin profile fields these 5 need) |
| Behaviour change | yes — 11 selectable coins removed |

## Problem

`TRENCHES_COINS` holds 16 entries. Three problems follow:

1. **Five have no art.** `client/public/assets/coins/` contains 11 PNGs
   (`stable, safu, growth, trend, volt, pump, moon, fresh, degen, apemax,
   legend`). `$FOMO`, `$WAGMI`, `$COPE`, `$REKT` and `$NGMI` were added
   later and have no matching file, so
   `TextureLoader().load('/assets/coins/${coin.id}.png')` 404s and those
   discs render untextured.

2. **They break the mastery payoff.** `docs/FEATURES.md` calls `$LEGEND`
   "the strongest speed/risk profile in the game," gated behind Trenches
   Mastery Lv. 5. It isn't — four freely-available coins are faster
   (top speed = `base + cap`, per `i4.md`):

   | Coin | top speed | unlocked? |
   |---|---|---|
   | `$NGMI` | **36.4** | yes, from the start |
   | `$REKT` | 34.4 | yes |
   | `$COPE` | 32.4 | yes |
   | `$WAGMI` | 30.4 | yes |
   | `$LEGEND` | **30.5** | **no — Mastery Lv. 5** |

   The reward for five cash-outs is beaten by what a new player can pick
   immediately.

3. **They contradict every doc.** `README.md`, `docs/FEATURES.md` and this
   file's own header all describe 10 coins + `$LEGEND`.

Underneath all three is a design problem the count makes worse: every coin
varies on **one axis** — candle approach speed. Sixteen graduated steps of
one variable is a difficulty slider wearing a coin gallery's clothes, and
the only way to make a coin "interesting" is to make it faster, which is
how the table reached 16 in the first place.

## Recommended Fix

Cut to **five** coins, each differing on an axis you can name in a sentence.
Four selectable plus `$LEGEND` as the mastery unlock, all five with existing
art. `i9.md` adds the per-coin fields (`red`, `fuseMul`, `payMul`,
`holeChance`) that make the axes real; this patch is the roster and the
speed profile only, and is safe to land first.

| Coin | Axis | Top speed |
|---|---|---|
| `$STABLE` | Forgiving — the teaching coin | 5.5 |
| `$VOLT` | Reading test — punishes misreading, not slow hands | 11.0 |
| `$MOON` | Front-loaded — fast at once, barely ramps | 14.5 |
| `$APEMAX` | Escalation — starts fair, ends unplayable | 22.5 |
| `$LEGEND` | All of it, and the top of the ladder | 26.0 |

`$MOON` opens faster than `$APEMAX` (13.0 vs 11.0) but ends far slower
(14.5 vs 26.0): same difficulty budget, opposite shape of run. That
distinction is impossible to express on a single speed axis and is the
clearest argument for profiles over steps.

## Migration

`getLastCoinId()` reads a coin id from localStorage, so returning players
may hold one of the 11 removed ids:

- `getCoinById` already falls back to `TRENCHES_COINS[1]` for an unknown id.
- `focusedCoinIndex` uses `findIndex(...)`, which returns `-1`, already
  guarded by `Math.max(0, ...)`.

No migration code needed — but the fallback index now means `$VOLT` rather
than `$SAFU`, and the documented default ("last-picked coin, pre-selected
next visit") never mentioned a hard-coded default at all. Worth making the
fallback explicit: `getCoinById(id)` returning the `stable` entry is a
friendlier first-run default than the second-hardest coin.

## Follow-on

The six coins removed that *do* have art (`safu, growth, trend, pump,
fresh, degen`) can come back later as **profiles**, not speed steps — each
would need a nameable axis of its own and a top speed below 26.0. The five
with no art need art first.
