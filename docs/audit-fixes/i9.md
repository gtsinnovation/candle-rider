# Change: give each coin a profile (red rate, fuse length, payout, void rate), not just a speed

| Field | Value |
|---|---|
| Files | `client/src/scenes/paths/trenchesCoins.js`, `client/src/scenes/paths/TrenchesScene.js` |
| Category | Balance / Design |
| Severity | medium (design, not a defect) |
| Effort | Medium |
| Depends on | `i5.md` (roster trim), `i6.md` (per-lane rows — required for `holeChance`) |
| Behaviour change | yes — this is a balance change, deliberately |

## Problem

After `i5.md` the roster is coherent, but every coin still varies on **one
axis**: how fast candles approach. `base`, `ramp` and `rampCap` are the only
per-coin fields, and everything else that shapes a run is a module-level
constant shared by all of them:

| Lever | Where it lives | Same for every coin? |
|---|---|---|
| Red spawn rate | `RED_SPAWN_CHANCE = 0.28` (`:783`) | yes |
| Fuse length | `fuseMin = 1800, fuseRange = 2600` (`:817`) | yes |
| Bag per landing | `gain` at `:1254` | yes |
| Riding accrual | `addBag(6 * dt)` (`:1272`) | yes |
| Red-landing cost | `addBag(-6)` (`:1260`) | yes |

So ten graduated steps of one variable is a difficulty slider wearing a coin
gallery's clothes. The player isn't choosing a strategy — they're choosing a
number, and the coin room's free-look camera, individual art and lore copy
are all selling a decision the mechanics don't deliver.

It also makes the roster hard to reason about: the only way to make a coin
"more interesting" is to make it faster, which is why the table drifted to 16
entries in the first place.

## Recommended change

Five coins, each differing on an axis you can name in a sentence. Speed
stays a differentiator but stops being the *only* one.

| Coin | Axis | What it actually asks |
|---|---|---|
| `$STABLE` | **Forgiving** | Slow, few reds, long fuses, no voids. The teaching coin. |
| `$VOLT` | **Reading test** | Moderate speed, but reds everywhere and fuses that snap. Punishes misreading, not slow hands. |
| `$MOON` | **Front-loaded** | Fast from tick one, barely ramps. Sparse footing — the jump matters. |
| `$APEMAX` | **Escalation** | Starts fair, ends unplayable. The ramp is the whole story. |
| `$LEGEND` | **All of it** | Every axis at once, and the top of the ladder. Mastery Lv. 5. |

Note `$MOON` and `$APEMAX` invert relative to each other: `$MOON` opens
faster (13.0 vs 11.0) but `$APEMAX` ends far faster (26.5 vs 14.5). Two coins,
same rough difficulty budget, completely different shape of run — which is
the point, and is impossible to express with a single speed axis.

## Proposed change

Four new optional fields per coin. All default to today's behaviour when
absent, so the patch is safe to land incrementally:

```diff
+// Per-coin profile. Each field defaults to the module constant it overrides,
+// so a coin that omits them behaves exactly as coins do today.
+//
+// red        — chance a candle spawns already-red (default RED_SPAWN_CHANCE)
+// fuseMul    — multiplies fuse length; <1 = snappier flips (default 1)
+// payMul     — multiplies Bag per green landing (default 1)
+// holeChance — chance a lane is left empty in a row, per i6's spawnRow (default 0)
 export const TRENCHES_COINS = [
-  { id: 'stable', symbol: '$STABLE', name: 'Blue Chip Reserve', color: 0x50ff96, base: 3.2, ramp: 0.038, rampCap: 2.3 },
+  { id: 'stable', symbol: '$STABLE', name: 'Blue Chip Reserve', color: 0x50ff96,
```

Read sites in `TrenchesScene.js` — four one-line changes:

```diff
-    let startColor = forcedColor || (Math.random() < RED_SPAWN_CHANCE ? 'red' : 'green');
+    const redChance = difficulty.red ?? RED_SPAWN_CHANCE;
+    let startColor = forcedColor || (Math.random() < redChance ? 'red' : 'green');
```

```diff
     let fuseMin = 1800, fuseRange = 2600;
     if (activeEvent === 'pump') { fuseMin = 6000; fuseRange = 2000; }
     else if (activeEvent === 'fud') { fuseMin = 400; fuseRange = 600; }
+    // Coin profile scales the fuse on top of any active market event.
+    const fuseMul = difficulty.fuseMul ?? 1;
+    fuseMin *= fuseMul; fuseRange *= fuseMul;
```

```diff
-              gameState.addBag(gain);
+              gameState.addBag(gain * (difficulty.payMul ?? 1));
```

and `holeChance` feeds `spawnRow` from `i6.md` (lane left empty, never all
three, at least one green per row).

`spawnCandle` reads `difficulty`, which is assigned in `apeIntoCoin` before
any gameplay spawn — but the **initial 24-candle seed loop runs at mount**,
before a coin is picked, using the `getLastCoinId()` default. `apeIntoCoin`
already refreshes every candle's `flipAt` for exactly this reason; it must
now also re-roll their colours, or the first ~24 candles of every run carry
the previous coin's red rate:

```diff
     candles.forEach((c) => {
-      if (c.color !== 'green') return;
+      // Re-roll colour to the chosen coin's profile — the seed loop ran at
+      // mount with whatever getLastCoinId() returned, not this coin.
+      if (c !== startCandle) {
+        const newColor = Math.random() < (coin.red ?? RED_SPAWN_CHANCE) ? 'red' : 'green';
+        if (newColor !== c.color) { c.color = newColor; c.mesh.material.color.set(newColor === 'red' ? RED : GREEN); }
+      }
+      if (c.color !== 'green') return;
       const travelSeconds = Math.abs(c.mesh.position.z) / Math.max(coin.base, 0.1);
-      c.flipAt = now + travelSeconds * 1000 + 1800 + Math.random() * 2600;
+      const fm = coin.fuseMul ?? 1;
+      c.flipAt = now + travelSeconds * 1000 + 1800 * fm + Math.random() * 2600 * fm;
     });
```

`startCandle` must stay green — it is the guaranteed platform.

## Surfacing it

The coin room currently shows `symbol — name` in `coinLabel`. With profiles,
the *axis* is the thing the player needs to pick on, and speed alone no
longer describes the coin. Show the axis and a one-line note rather than
(or alongside) the name — otherwise the differentiation exists in the code
and nowhere the player can see it.

## Validation

The prototype in this project runs this exact roster with these fields
(`Trenches Core Loop.dc.html`, `COINS` array) and all five are playable and
distinct. Two calibration notes from playing it:

- `$MOON`'s `holeChance: 0.22` is the most likely number to be wrong — it
  makes the jump the primary skill, which is a bigger shift than the other
  four coins ask for. Try 0.15 first.
- `$VOLT` at `red: 0.38` with `fuseMul: 0.55` is genuinely harder than
  `$APEMAX` for the first ~20 seconds, despite being much slower. That
  reads as correct (it is a different axis, not a lower difficulty) but it
  does mean the coin room's implied left-to-right difficulty ordering no
  longer holds — worth deciding whether the arc should still be ordered by
  speed at all.
