# Fix: `cap` in trenchesCoins.js bounds the RAMP, not the speed — every doc and comment reads it the other way

| Field | Value |
|---|---|
| Files | `client/src/scenes/paths/trenchesCoins.js`, `client/src/scenes/paths/TrenchesScene.js` |
| Category | Correctness / Maintainability |
| Severity | high |
| Effort | Low |
| Behaviour change | none (pure rename + derived field) |

## Problem

`TrenchesScene.js:1150` computes the run's scroll speed as:

```js
speed = difficulty.base + Math.min(elapsed * difficulty.ramp, difficulty.cap);
```

`cap` is therefore the ceiling on the **ramp term**, not on speed. The real
maximum speed of a coin is `base + cap`. But every name, comment and doc
treats it as a speed ceiling:

- `trenchesCoins.js` header: "each coin sets the run's full candle-approach speed profile (base/ramp/cap)"
- `README.md` / `docs/FEATURES.md` describe coins as having "its own base speed / ramp rate / speed cap"

The two readings disagree by a lot, and the field's value makes the wrong
reading look plausible — for `$STABLE`, `base: 3.2` with `cap: 2.3` reads as
a cap *below* the base speed, which is nonsense under the documented meaning
but correct under the actual one:

| Coin | base | cap | max speed (`base + cap`) | max speed if `cap` were a true ceiling |
|---|---|---|---|---|
| `$STABLE` | 3.2 | 2.3 | **5.5** | 2.3 (slower than its own base) |
| `$SAFU` | 4.05 | 3.15 | **7.2** | 3.15 |
| `$VOLT` | 8.1 | 6.3 | **14.4** | 6.3 |
| `$APEMAX` | 15.0 | 11.5 | **26.5** | 11.5 |
| `$NGMI` | 21.0 | 15.4 | **36.4** | 15.4 |
| `$LEGEND` | 17.0 | 13.5 | **30.5** | 13.5 |

The risk is not that the game is currently wrong — the arithmetic does what
the author intended. The risk is that the next person to read the file
"fixes" it to match the documentation:

```js
speed = Math.min(difficulty.base + elapsed * difficulty.ramp, difficulty.cap); // WRONG — silently rebalances all 16 coins
```

That one-line change would clamp `$STABLE` to 2.3 (below its base), make
every coin slower than its starting speed, and invert the difficulty
ordering — with no test to catch it.

## Recommended Fix

Rename the field to say what it does, and expose the derived value the docs
were reaching for. No gameplay numbers change.

1. Rename `cap` → `rampCap` on all 16 coin definitions.
2. Add a `maxSpeed(coin)` helper (`base + rampCap`) and use it wherever a
   coin's top speed is displayed or reasoned about.
3. Update the one read site in `TrenchesScene.js` and correct the file
   header comment, `README.md` and `docs/FEATURES.md`.

Grep for `\.cap\b` before merging — the field is read in exactly one place
(`TrenchesScene.js:1150`), but the rename must land on all 16 definitions in
the same commit or every coin's ramp becomes `undefined` and `speed`
collapses to `NaN`.

## Proposed Change

`client/src/scenes/paths/trenchesCoins.js`:

```diff
-// candle-approach speed profile (base/ramp/cap), replacing the old
+// candle-approach speed profile (base/ramp/rampCap), replacing the old
 // Beginner/Middle/Master tier system entirely.
+//
+// base    — scroll speed at t=0
+// ramp    — speed added per second of run time
+// rampCap — ceiling on the RAMP TERM, not on speed. A coin's top speed is
+//           base + rampCap (see maxSpeed below). This is why several coins
+//           have a rampCap lower than their own base — that is correct.

-  { id: 'stable',   symbol: '$STABLE',  name: 'Blue Chip Reserve', color: 0x50ff96, base: 3.2,  ramp: 0.038, cap: 2.3 },
+  { id: 'stable',   symbol: '$STABLE',  name: 'Blue Chip Reserve', color: 0x50ff96, base: 3.2,  ramp: 0.038, rampCap: 2.3 },
```

...applied identically to all 16 entries (`safu`, `growth`, `trend`, `volt`,
`pump`, `moon`, `fresh`, `degen`, `apemax`, `fomo`, `wagmi`, `cope`, `rekt`,
`ngmi`, `legend`), plus:

```diff
+// A coin's actual top speed. Use this for any UI or balance reasoning about
+// "how fast does this coin get" — never read rampCap on its own.
+export function maxSpeed(coin) {
+  return coin.base + coin.rampCap;
+}
```

`client/src/scenes/paths/TrenchesScene.js`:

```diff
-      speed = difficulty.base + Math.min(elapsed * difficulty.ramp, difficulty.cap);
+      // Ramp term is capped, NOT speed — top speed is base + rampCap.
+      speed = difficulty.base + Math.min(elapsed * difficulty.ramp, difficulty.rampCap);
```

`README.md` and `docs/FEATURES.md`:

```diff
-  each with its own base speed / ramp rate / speed cap
+  each with its own base speed / ramp rate / ramp cap (top speed = base + ramp cap)
```

## Also worth a look while in this file (not part of this fix)

- **Coin count drift.** `TRENCHES_COINS` holds **16** entries; `README.md`,
  `docs/FEATURES.md` and the file's own header all say 10 (+ `$LEGEND`).
  `$FOMO`, `$WAGMI`, `$COPE`, `$REKT` and `$NGMI` were added and never
  documented.
- **Five coins have no art.** `client/public/assets/coins/` contains 11 PNGs
  (`stable, safu, growth, trend, volt, pump, moon, fresh, degen, apemax,
  legend`). The five undocumented coins above have no matching file, so
  `TextureLoader().load('/assets/coins/${coin.id}.png')` 404s and those
  discs render untextured.
- **`getLastCoinId()` defaults to `'safu'`**, not the documented
  "last-picked coin, pre-selected next visit" — correct as a first-visit
  default, but the doc doesn't mention it.
